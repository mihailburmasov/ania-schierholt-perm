## Что сделано (v1)

- **Каталог:** 40 моделей, 44 цвета, 7 категорий, 29 образов из двух PDF (лукбук AW26, обзор брюк K33). Фото извлечены из PDF в исходном разрешении, без надписей поверх.
- **Модель данных:** товар = модель + ткань, как в артикуле бренда (`HO 3389/69`); цвета — варианты внутри товара. Префиксы: HO брюки, JA жакеты, BL блузы, MA пальто, WE жилеты, RO юбка, TO топ. «HO 3396/66» из каталога брюк на самом деле юбка — объединена с RO 3396.
- **Страницы:** главная, каталог и 7 страниц категорий (фильтр по цвету и укороченной длине), 40 страниц товаров, лукбук, бутик с картой, доставка/оплата/возврат с таблицей размеров, корзина, «спасибо», 404, политика, согласие на обработку ПД.
- **Карточка товара:** цвет (параметр `?c=` в адресе), размеры DE/RU, «Помочь с размером», длина для моделей с укороченной версией, блок «Образ целиком» с кнопкой «добавить образ», закреплённая кнопка «В корзину» на мобильных.
- **Заявки:** `server/send.php` — проверки на сервере, ловушка для ботов, ограничение частоты, письмо (SMTP или `mail()`), по желанию Telegram, журнал `orders/ГГГГ-ММ.log.php` (защищён от чтения снаружи на любом сервере).
- **Под рекламу:** цели Метрики (`cart_add`, `look_add`, `order_send`, `callback_send`, `question_send`, `phone_click`, `messenger_click`), электронная коммерция через `dataLayer`, UTM и yclid (первый и последний визит) уходят в письмо с заявкой, заготовка YML-фида (заполнится, когда появятся цены).
- **SEO:** canonical, OG-картинка, schema.org (ClothingStore, Product, BreadcrumbList, FAQPage), sitemap, robots с `Clean-param`.
- **Проверено:** все сценарии в headless Chrome (покупка целиком, валидация, мобильная версия 375–390 px, демо на живом Pages). 54 страницы из sitemap отвечают 200, битых ссылок нет.

Подробная инструкция (структура, добавление каталогов, выкладка) — в [README.md](README.md).

## Как работать

```bash
npm install
npm run build                 # dist/ — боевая сборка; в конце печатает список незаполненных заглушек
cp server/config.php dist/ && npm run serve    # локально: http://localhost:8000
npm run deploy:demo           # пересобрать и выложить демо на GitHub Pages
npm run extract:all           # заново извлечь фото из PDF (нужны PDF в _source/catalogs/)
```

`server/config.php` в git нет. Локальный тестовый конфиг: `log_only => true`, адрес `test@example.ru`. Режим `log_only` срабатывает только на localhost, поэтому выложенный по ошибке тестовый конфиг не «съест» реальные заявки: форма покажет ошибку.

## Решения и почему

- **Название «Studio 60»** — рабочее, придумано мной (клиент разрешил): «60» от адреса. Меняется в `data/site.json`.
- **Статика + PHP, а не CMS:** быстро, дёшево, хорошо для рекламы. Если клиенту понадобится самому править товары — скилл `php-json-admin` (админка поверх тех же JSON).
- **Хостинг нужен с PHP** (Beget, Timeweb) из-за `send.php`. Yandex Object Storage, где обычно лежат сайты пользователя, не подходит без переделки формы. **Не решено** — ждём ответа пользователя.
- **PDF-каталоги не в git:** репозиторий публичный, а в PDF есть телефоны и почты сотрудников и агентов бренда. В git лежат извлечённые фото в JPEG 92% (`_source/raw/`, около 8 МБ).
- **Описания товаров** составлены по фото. Состав ткани не выдуман — ждём от клиента. Непроверяемые детали (шлица, молния) убраны.
- **Галочка согласия не проставлена заранее** — так безопаснее с учётом 152-ФЗ.
- **Порядок фото в галерее:** пэкшот (если есть), затем образы, где меньше вещей (сама вещь виднее). Обложку можно задать вручную полем `cover` у варианта в `products.json`.

## Подводные камни

- **Git Bash на Windows** превращает `BASE=/studio60-perm` в путь `C:/Program Files/Git/...`. Нужен `MSYS_NO_PATHCONV=1` (в `deploy:demo` уже прописан).
- **GitHub Actions не подключён:** у токена gh нет права `workflow`, и пуш файлов `.github/workflows/` отклоняется. На новом пустом репозитории это маскировалось ошибкой 500. Подключить: `gh auth refresh -s workflow` (вход через браузер), затем вернуть сценарий сборки.
- **Карта Яндекса** в headless-браузере не прорисовала тайлы (место нашла). Нужно посмотреть глазами в обычном браузере.
- **Cookie-баннер** нарочно маленький и в левом нижнем углу: широкий баннер на ПК перекрывал кнопку «В корзину».
- **Классификатор безопасности** дважды запретил читать `config.php`, `README.md` и `send.php` соседнего проекта Okna_remont. Обработчик заявок написан заново, к тем файлам не возвращаться.
- **Политика конфиденциальности** не упоминает Telegram. Если включить дублирование заявок в Telegram, политику нужно дополнить (иностранный сервис).
- **Новый лукбук:** путь к фото задаётся в `data/looks.json` (`image`), коллекция — в `collections`. Команду извлечения добавить в скрипт `extract:all`.
