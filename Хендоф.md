- **Репозиторий:** https://github.com/mihailburmasov/studio60-perm (публичный, ветка `main`; демо-сборка — ветка `gh-pages`).

- **Исходники клиента:** `D:\Claude\Создание сайтов\Клиенты\Ольга Пермь Одежда` (ТЗ в `Промт.docx`, PDF-каталоги в `Каталоги/`).
- **Банк изображений бренда:** https://imagebank-ania-schierholt.px.media/overview — открытый, без входа (логотип, лукбуки, фото брюк, материалы для соцсетей).

## Что сделано

- **Каталог:** 40 моделей, 44 цвета, 7 категорий, 29 образов (лукбук AW26 и обзор брюк K33).
- **Фото:** лукбук — из банка бренда в 1748×2480 (вдвое крупнее, чем в PDF), цвет подогнан под PDF; у 16 брюк и юбки по 3 ракурса (спереди, сбоку, сзади). Подробно — README, раздел «Банк изображений бренда».
- **Модель данных:** товар = модель + ткань, как в артикуле бренда (`HO 3389/69`); цвета — варианты внутри товара. Префиксы: HO брюки, JA жакеты, BL блузы, MA пальто, WE жилеты, RO юбка, TO топ. «HO 3396/66» из каталога брюк на самом деле юбка — объединена с RO 3396.
- **Страницы:** главная, каталог и 7 страниц категорий (фильтр по цвету и укороченной длине), 40 страниц товаров, лукбук, бутик с картой, доставка/оплата/возврат с таблицей размеров, корзина, «спасибо», 404, политика, согласие на обработку ПД.
- **Карточка товара:** цвет (параметр `?c=` в адресе), размеры RU / DE (российский крупно, немецкий мелко — так же в корзине, заявке и таблице), «Помочь с размером», длина для моделей с короткой версией, блок «Образ целиком» с кнопкой «добавить образ», закреплённая кнопка «В корзину» на мобильных.
- **Корзина:** выдвижная панель на ПК с «Удалить» у каждой вещи, «Очистить корзину» (с подтверждением) в панели и на странице корзины. В форме заявки нет выбора «Как с вами связаться» (убран по просьбе пользователя).
- **Бренд:** в шапке и подвале — логотип Ania Schierholt (SVG из банка, `src/brand/`) и подпись «Бутик в Перми». Фавикон и превью ссылок (og:image) — монограмма «A» бренда; у страниц товаров превью — фото товара.
- **Заявки:** `server/send.php` — проверки на сервере, ловушка для ботов, ограничение частоты, письмо (SMTP или `mail()`), по желанию Telegram, журнал `orders/ГГГГ-ММ.log.php` (защищён от чтения снаружи на любом сервере).
- **Под рекламу:** цели Метрики (`cart_add`, `look_add`, `order_send`, `callback_send`, `question_send`, `phone_click`, `messenger_click`), электронная коммерция через `dataLayer`, UTM и yclid (первый и последний визит) уходят в письмо с заявкой, заготовка YML-фида (заполнится, когда появятся цены).
- **SEO:** canonical, og:image, schema.org (ClothingStore, Product, BreadcrumbList, FAQPage), sitemap, robots с `Clean-param`.
- **Проверено:** сценарии в headless Chrome (покупка, удаление и очистка корзины, валидация, мобильная версия 375–390 px, демо на живом Pages).

Подробная инструкция (структура, добавление каталогов, банк изображений, выкладка) — в [README.md](README.md).

## Как работать

```bash
npm install
npm run build                 # dist/ — боевая сборка; в конце печатает список незаполненных заглушек
cp server/config.php dist/ && npm run serve    # локально: http://localhost:8000
npm run deploy:demo           # пересобрать и выложить демо на GitHub Pages
npm run extract:all           # заново извлечь фото из PDF (нужны PDF в _source/catalogs/)
```

`server/config.php` в git нет. Локальный тестовый конфиг: `log_only => true`, адрес `test@example.ru`. Режим `log_only` срабатывает только на localhost, поэтому выложенный по ошибке тестовый конфиг не «съест» реальные заявки: форма покажет ошибку.

## Решения и почему

- **Название магазина на сайте — «Ania Schierholt в Перми»** (поле `shopName` в `data/site.json`): подвал, заголовки вкладок, schema.org, og:site_name, YML-фид. Рабочее название «Studio 60» по просьбе пользователя убрано с сайта полностью; осталось только в имени репозитория и адресе демо. В заголовках, где бренд и «в Перми» уже есть («Женские брюки Ania Schierholt — купить в Перми»), суффикс не добавляется, чтобы не повторяться.
- **Цвет лукбука подогнан под PDF, а не взят из банка как есть** — пользователь решил оставить так. В банке «Muschel» уходит в хаки, «Anthra» в зелень, а предметные фото брюк совпадают с PDF; без подгонки одни и те же брюки на предметном фото и в образе были бы разного цвета. Образ 6 (`aw26-p06-1`) — из PDF: в банке соседний кадр.
- **Статика + PHP, а не CMS:** быстро, дёшево, хорошо для рекламы. Если клиенту понадобится самому править товары — скилл `php-json-admin` (админка поверх тех же JSON).
- **Хостинг нужен с PHP** (Beget, Timeweb) из-за `send.php`. Yandex Object Storage, где обычно лежат сайты пользователя, не подходит без переделки формы. **Не решено** — ждём ответа пользователя.
- **PDF-каталоги не в git:** репозиторий публичный, а в PDF есть телефоны и почты сотрудников и агентов бренда. В git — фото: из PDF (`_source/raw/aw26`, `_source/raw/hosen`) и из банка (`_source/raw/bank`, около 18 МБ).
- **Описания товаров** составлены мной по фото, у бренда текстов нет. Состав ткани не выдуман — ждём от клиента. Непроверяемые детали (шлица, молния) убраны, но в части описаний есть догадки о материале (например, «комфорт трикотажа» у HO 3383) — проверить, когда придут составы.
- **Названия цветов** — из каталогов бренда (Anthra, Muschel, Caper…), переведены; «Ракушка (бежевый)», «Каперс (оливковый)» — пояснения в скобках добавлены мной. Оттенки кружков подобраны по фото.
- **Галочка согласия не проставлена заранее** — так безопаснее с учётом 152-ФЗ.
- **Порядок фото в галерее:** предметные фото (первое — обложка карточки), затем образы, где меньше вещей (сама вещь виднее). Обложку образа можно задать полем `cover` у варианта в `products.json`.

## Что ждём от клиента

Все заглушки — в `data/site.json` (поля `_..._todo`). Сборка перечисляет незаполненное.

- **короткая длина брюк:** как называть и на какой рост. В каталоге K33 — «optional auch in kurz»; на сайте пока «есть укороченные» / «Укороченная». Пользователь решил **ждать ответа Ольги**, до этого не менять (вероятный вариант — «для невысоких»);
- какие модели есть в бутике, каких нет — позиции каталога до этого **не менять** (в т. ч. не добавлять HO 3387/55 Muschel, хотя фото в банке есть);
- WhatsApp, Telegram (телефон получен: +7 951 936-11-15);
- почта для заявок и SMTP (Яндекс 360 — пароль приложения). На сайте пока заглушка `info@` (поле `email` в `data/site.json`);
- реквизиты продавца (ИП/ООО, ИНН, ОГРН/ОГРНИП; сейчас на сайте просто «ИП», пустые ИНН/ОГРН не выводятся) — без них не пройти модерацию Директа;
- часы работы бутика (сейчас стоит 10:00–21:00 ориентировочно), этаж/павильон в ТЦ;
- домен (в коде условный `example.ru`; от него строятся canonical, sitemap, og:image — поэтому на демо превью ссылок не показывается);
- номер счётчика Метрики;
- цены (поле `price`), состав тканей, по возможности описания от поставщика;
- подтвердить условия доставки, оплаты и возврата (на сайте: возврат 7 дней при доставке, обмен 14 дней в бутике);
- подано ли уведомление в Роскомнадзор об обработке ПД;
- разрешает ли бренд использовать фото на сайте и в рекламе (страница «Nutzungsrechte» в банке пустая);
- по возможности — фото бутика и предметные фото жакетов и блуз (в банке бренда их нет);
- есть ли в бутике вещи весна–лето 2026: в банке есть лукбук SS 26 и фото брюк, но без артикулов — нужен PDF-каталог SS 26.

## Подводные камни

- **Название в YML-фиде** — «Ania Schierholt в Перми» (23 символа). Не проверено, примет ли его модерация Директа/Товаров (требования к длине и совпадению с названием на сайте). Если нет — сократить `shopName` до «Ania Schierholt».
- **Фото из банка:** перед заменой сверять цвет с PDF; файлы банка в профиле eciRGB v2 — сборка (sharp) переводит в sRGB корректно, проверено. Скрипты — `tools/imagebank/`, ссылки на оригиналы — `_source/raw/bank/manifest.json`. `npm run extract:all` перезаписывает только `_source/raw/aw26` и `_source/raw/hosen`, папку `bank` не трогает.
- **HO 3384/69:** в PDF K33 у неё стоит фото модели HO 3384/55, своих снимков в банке нет — так и осталось.
- **Сборка чистит `dist/img`:** удаляет картинки, которые не сгенерированы в текущей сборке. Если добавлять картинки в `dist/img` в обход `img()` — добавить их в `usedImg` (как `og.jpg`).
- **Замены в JS через `String.replace`:** `$$` в строке замены превращается в `$` — так однажды сломались вызовы `$$(...)` в `app.js`. Для правок кода скриптом использовать `split().join()`.
- **Git Bash на Windows** превращает `BASE=/studio60-perm` в путь `C:/Program Files/Git/...`. Нужен `MSYS_NO_PATHCONV=1` (в `deploy:demo` уже прописан).
- **GitHub Actions не подключён:** у токена gh нет права `workflow`, и пуш файлов `.github/workflows/` отклоняется. На новом пустом репозитории это маскировалось ошибкой 500. Подключить: `gh auth refresh -s workflow` (вход через браузер), затем вернуть сценарий сборки.
- **Карта Яндекса** в headless-браузере не прорисовала тайлы (место нашла). Нужно посмотреть глазами в обычном браузере.
- **Cookie-баннер** нарочно маленький и в левом нижнем углу: широкий баннер на ПК перекрывал кнопку «В корзину».
- **Классификатор безопасности** дважды запретил читать `config.php`, `README.md` и `send.php` соседнего проекта Okna_remont. Обработчик заявок написан заново, к тем файлам не возвращаться.
- **Политика конфиденциальности** не упоминает Telegram. Если включить дублирование заявок в Telegram, политику нужно дополнить (иностранный сервис).
- **Новый лукбук:** путь к фото задаётся в `data/looks.json` (`image`), коллекция — в `collections`. Команду извлечения добавить в скрипт `extract:all`; если сезон есть в банке бренда — брать фото оттуда (README).

## Следующие шаги

1. Получить ответ пользователя по хостингу и данные клиента. Заполнить `data/site.json` и `server/config.php`, пересобрать, чтобы список заглушек при сборке опустел.
2. Когда Ольга ответит про короткую длину и ассортимент — поправить подпись и позиции каталога.
3. Выложить `dist/` на хостинг, положить рядом боевой `config.php`, отправить тестовую заявку и проверить письмо. Проверить превью ссылки в Telegram/WhatsApp на боевом домене.
4. В Метрике создать цели (JavaScript-события, список выше) и включить электронную коммерцию.
5. Когда придут цены — заполнить `price`, пересобрать, проверить `feed.yml`, подключить его в Директе/Товарах.
6. Новые каталоги — по README, разделы «Как добавить новый каталог» и «Банк изображений бренда».
