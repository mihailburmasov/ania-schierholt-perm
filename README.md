# Ania Schierholt в Перми

Сайт-каталог монобрендового бутика Ania Schierholt (Пермь, ул. Ленина, 60, ТЦ «Колизей Atrium»).
Работает как интернет-магазин без оплаты: покупательница выбирает модель, цвет, размер, кладёт вещи в корзину и отправляет запрос. Запрос приходит на почту (и, если настроить, в Telegram), консультант перезванивает.

Название магазина на сайте — «Ania Schierholt в Перми» (поле `shopName` в `data/site.json`). Рабочее название «Studio 60» убрано полностью (2026-10-08–09): на сайте, в почте, домене-заглушке, политике и согласии — только бренд Ania Schierholt. Оно осталось лишь в имени репозитория и адресе демо (клиенту не показывается).

## Устройство

| Что | Где |
|---|---|
| Факты о магазине: телефон, адрес, часы, реквизиты, Метрика | `data/site.json` — **единственный источник**, в шаблонах ничего не вписано руками |
| Товары, категории, цвета, цены, описания | `data/products.json` |
| Образы из лукбука (какие вещи на каком фото) | `data/looks.json` |
| Исходные PDF-каталоги | `_source/catalogs/` (в git не хранятся — в них контакты сотрудников бренда; оригиналы в папке клиента) |
| Фото, извлечённые из PDF (JPEG 92%) | `_source/raw/<каталог>/` — перезаписываются командой `npm run extract:all` |
| Фото из банка изображений бренда (выше качеством) | `_source/raw/bank/` — `extract:all` их не трогает; откуда что взято — `_source/raw/bank/manifest.json` |
| Логотип бренда и исходник фавикона | `src/brand/` (из банка изображений, раздел Logo & Graphic) |
| Шаблоны страниц и сборка | `build.mjs` |
| Стили / скрипты | `src/css/style.css`, `src/js/app.js` |
| Приём заявок | `server/send.php` + `server/config.php` (образец — `config.sample.php`) |
| Готовый сайт | `dist/` (создаётся сборкой, в git не хранится) |

```bash
npm install          # один раз
npm run build        # собрать dist/
cp server/config.php dist/ && npm run serve   # проверить локально: http://localhost:8000
```

Для локальной проверки заявок в `server/config.php` стоит `'log_only' => true`: письмо не отправляется, заявка пишется в журнал `dist/orders/ГГГГ-ММ.log.php`. Этот режим срабатывает только на localhost — на хостинге с тестовым конфигом форма честно покажет ошибку, а не «потеряет» заявку. Сборка в конце печатает список незаполненных заглушек.

## Как добавить новый каталог

1. Положить PDF в `_source/catalogs/`.
2. Извлечь фото: `node tools/extract-catalog.mjs _source/catalogs/НОВЫЙ.pdf _source/raw/новый новый > _source/raw/новый.jsonl` (и добавить эту команду в скрипт `extract:all` в package.json).
   Скрипт сохраняет все встроенные фото в исходном разрешении (без надписей поверх) и печатает подпись под каждым фото — по ней видно артикул.
3. В `data/products.json` добавить товары. Товар = модель + ткань, как в артикуле бренда (`HO 3389/69`); цвета — варианты внутри товара. Префиксы бренда: HO — брюки, JA — жакет, BL — блуза, MA — пальто, WE — жилет, RO — юбка, TO — топ. Новый цвет — добавить в `colors`, новую категорию — в `categories`.
4. Если в каталоге есть образы (лукбук) — добавить их в `data/looks.json` (артикулы в формате `JA 3351/66 Caper`). Фото из образов сами попадут в галереи товаров и в блок «Образ целиком».
5. Если у каталога своя коллекция — добавить её в `collections` и указать её id в поле `collection` у образов.
6. `npm run build`. Сборка предупредит, если артикул из образа не найден в каталоге или у товара нет фото.

## Банк изображений бренда

https://imagebank-ania-schierholt.px.media/overview — открытый портал Ania Schierholt для партнёров: логотип, лукбуки (FW 26/27, SS 26), предметные фото брюк по 3 ракурса, фото для соцсетей. Файлы в высоком разрешении; если сезон есть в банке, фото берём оттуда, а не из PDF.

Как сделано для FW 26/27 (2026-10):
- **Лукбук.** В банке те же кадры, что в PDF, но 1748×2480 (в PDF — 879×1245). Цвет в банке обработан иначе: «Muschel» уходит в хаки, «Anthra» — в зелень, а предметные фото совпадают с цветом PDF. Поэтому высокое разрешение берём из банка, а цвет подгоняем под PDF:
  1. `node tools/imagebank/match.mjs _source/raw/aw26 <папка-банка> map.json` — какая страница PDF какому файлу банка (у верного совпадения расстояние в разы меньше второго кандидата);
  2. `node tools/imagebank/colormatch.mjs map.json _source/raw/aw26 <папка-банка> <выход1>` — общая поправка цвета по гистограммам;
  3. `node tools/imagebank/local-gain.mjs _source/raw/aw26 <выход1> _source/raw/bank/aw26 20` — плавная местная поправка (бренд в PDF правил цвет выборочно).
  Результат обязательно просмотреть глазами. Страница 6 (`aw26-p06-1`) в банке — соседний кадр, а не тот же, поэтому для неё оставлено фото из PDF.
- **Брюки и юбка.** Предметные фото в PDF K33 — это те же файлы банка, пиксель в пиксель. В банке по 3 ракурса (спереди, сбоку, сзади), поэтому поле `pack` в `products.json` может быть списком; первое фото — обложка карточки. У HO 3384/69 своих снимков в банке нет (в PDF стоит фото HO 3384/55) — осталось одно фото из PDF.
- Имена файлов брюк: `_HO338969an00207` = HO 3389/69, цвет Anthra (`an`; `mu` — Muschel; без суффикса — основной цвет модели из каталога K33), `00207` — номер кадра.

Права на фото: страница «Nutzungsrechte» на портале пустая; разрешение на использование фото на сайте и в рекламе — уточнить у клиента.

**Цены:** поле `price` у товара (число в рублях). Пока `null` — везде «Цена по запросу». Как только цены появятся — заполнится товарный фид `feed.yml` для Яндекс Директа / Товаров (сейчас пустой).

## Что нужно от клиента (заглушки, помечены TODO в `data/site.json`)

- телефон бутика, WhatsApp, Telegram;
- почта для заявок (в `server/config.php`) и данные SMTP (для Яндекс 360 — пароль приложения). Дублирование в Telegram возможно, но это иностранный сервис: при включении нужно дополнить политику конфиденциальности;
- реквизиты продавца: ИП/ООО, ИНН, ОГРН(ИП) — **обязательны** для дистанционной торговли и модерации Директа;
- часы работы бутика, этаж/павильон в ТЦ;
- домен;
- номер счётчика Яндекс Метрики;
- цены; состав тканей (сейчас в описаниях только то, что видно на фото);
- подтвердить условия: доставка (какие службы), способы оплаты, возврат 7 дней / обмен 14 дней;
- уведомление Роскомнадзора об обработке персональных данных (152-ФЗ) — если продавец ещё не подавал;
- подтверждение, что бренд/дистрибьютор разрешает использовать фото лукбука на сайте и в рекламе;
- по возможности — фото самого бутика и предметные фото вещей (пэкшоты) для жакетов и блуз: сейчас у них только фото из лукбука.

## Демо на GitHub Pages

`npm run deploy:demo` собирает сайт с `BASE=/studio60-perm` и публикует его в ветку `gh-pages` → `https://mihailburmasov.github.io/studio60-perm/`. (Автосборка через GitHub Actions не подключена: токену gh нужно право `workflow` — `gh auth refresh -s workflow`.) Это витрина для согласования с клиентом: закрыта от индексации (noindex, robots.txt), а форма заявки вместо отправки говорит, что это демо, и показывает телефон — на Pages нет PHP.

Локально собрать так же: `MSYS_NO_PATHCONV=1 BASE=/studio60-perm npm run build` (переменная `MSYS_NO_PATHCONV` нужна только в Git Bash на Windows).

## Выкладка на боевой хостинг

Нужен обычный хостинг **с PHP** (Beget, Timeweb и т.п.) — из-за `send.php`. Yandex Object Storage (статический хостинг) не подойдёт без переделки формы.
1. `npm run build`.
2. Залить содержимое `dist/` в корень сайта (вместе с `.htaccess`).
3. Положить рядом с `send.php` настоящий `config.php` (с `log_only => false`). В сборку он не попадает специально.
4. Отправить тестовую заявку, проверить почту.
5. В Метрике создать цели (JavaScript-событие): `cart_add`, `look_add`, `order_send`, `callback_send`, `question_send`, `phone_click`, `messenger_click`. Включить «Электронная коммерция» (контейнер `dataLayer`) — события add / detail / purchase уже отправляются.

## Под рекламу (Яндекс Директ)

- У каждой категории и каждого товара свой адрес: `/catalog/bryuki/`, `/product/bryuki-3389-69/?c=anthra` (параметр `c` открывает нужный цвет) — объявления можно вести прямо на товар.
- Метки `utm_*` и `yclid` запоминаются при первом и последнем заходе и приходят в письме с заявкой — видно, какое объявление привело покупательницу.
- Цели и электронная коммерция Метрики — см. выше; на цель `order_send` можно оптимизировать кампании.
- `robots.txt` склеивает UTM-метки (`Clean-param`), корзина и «спасибо» закрыты от индексации.
- Юридический минимум для модерации: политика конфиденциальности, отдельное согласие на обработку данных (галочка не проставлена заранее), реквизиты в подвале, страница доставки и возврата.

## Анализ конкурентов и что взято в сайт

Российские магазины брендовой одежды (крупные универмаги и небольшие бутики) обычно страдают от одного из двух: либо тяжёлый маркетплейс с оплатой и десятками шагов, либо бутик живёт только в соцсетях, а сайт — визитка без каталога и с «ценой по запросу» без фото. Сильные стороны европейских fashion-магазинов (Mytheresa, Net-a-Porter, Breuninger, Zalando, COS) — подача вещей в образах, понятная размерная сетка с пересчётом, резерв товара для примерки в магазине, чистая типографика и крупные фото.

> Анализ сделан по общему знанию рынка и паттернов e-commerce (плюс исследования Baymard о размерных таблицах), а не по детальному аудиту каждого сайта.

Что сделано на сайте:
- **«Образ целиком»**: под каждым товаром — образ из лукбука со всеми вещами и кнопка «Добавить образ целиком» (приём «носите вместе с», типичный для европейских люксовых магазинов). Повышает средний чек.
- **Лукбук как витрина**: отдельная страница с 29 образами, у каждого — состав и добавление в один клик.
- **Капсулы по цветам** (каперс / ракушка / антрацит): коллекция бренда строится на трёх цветах, поэтому сайт продаёт гардероб, а не отдельные вещи.
- **Резерв на примерку** в бутике (как резерв в магазине у крупных европейских ритейлеров): в заявке — «Примерка и самовывоз в бутике».
- **Размеры DE + RU** прямо на кнопках, таблица размеров во всплывающем окне, вариант «Помочь с размером» вместо отказа от покупки.
- **Без оплаты и регистрации**: 3 поля обязательны (имя, телефон, согласие), выбор «звонок / WhatsApp / Telegram».
- **Мобильная версия**: листаемая галерея, закреплённая кнопка «В корзину», фильтры по цвету и длине, категории прокручиваются.
- **Честность и доверие**: «В наличии в Перми», адрес и карта, реквизиты, условия возврата по закону.
